# Agent instructions

Read this file first, then the nearest `AGENTS.md` and [docs/client-brief.md](docs/client-brief.md) / [docs/architecture/overview.md](docs/architecture/overview.md) for domain work.

## Repository state

- `backend/`: FastAPI app at `src/ai_dating` with `/healthz`, `/readyz`, typed config, SQLAlchemy/Alembic, transactional outbox and ClickHouse relay. Lockfile: `backend/uv.lock`.
- `frontend/`: Vite/React/TypeScript SPA; lockfile `frontend/pnpm-lock.yaml`. Status page calls `GET /healthz`. Local register/login hold an opaque session; Keep me signed in stores it in `localStorage`, otherwise `sessionStorage`.
- `docs/`: proposed product and architecture contracts. No CI or cloud deployment config yet.
- Target stack is FastAPI, React/Vite/TypeScript and Yandex Cloud: Managed PostgreSQL with pgvector/PostGIS, Object Storage, AI Studio and one Compute VM for the modular backend processes. Yandex AI Studio is the generation provider; GigaChat `EmbeddingsGigaR` is the retrieval embedding provider. Local prototype authentication is application-owned `login + password` with DB-backed sessions; phone OTP/call-code and Yandex ID are Later, before closed beta. Treat this as a design constraint, not evidence of deployed infrastructure.

See [README.md](README.md) for the full local sequence. Do not invent extra install/dev/CI commands.

```bash
cd backend && uv sync --dev
```

## Boundaries

- Keep one modular backend. Split processes for API, DB-backed jobs and outbox relay, not domain microservices, until documented triggers are met.
- Postgres is transactional source of truth. Media bytes live in object storage; ClickHouse is analytics, never authorization state.
- Enforce reciprocal eligibility, block, visibility and moderation before ranking and again before delivery. LLM/embeddings cannot override hard filters.
- Follow the canonical API, event envelope and IDs in `docs/architecture`. Do not emit analytics by dual-write; domain transaction writes the outbox.
- Never expose precise location, DOB, private facts, blocks/reports, moderation signals, model prompts/scores or service credentials to clients.
- Local-password auth must refuse non-local environment or non-loopback binding under `docs/authentication/design.md`. Future SMS exemptions must never become an authentication bypass.
- No social scraping/import or agent action on a user's behalf without a separately approved consent design.

## Changes

- Backend config has one source of truth: `backend/src/ai_dating/config.py` when created. Frontend env reads go only through `frontend/src/lib/env.ts`.
- Alembic is the only production schema path once installed. Review autogenerated migrations; write extensions, RLS, grants, partial/GiST/HNSW indexes explicitly. Never edit production schema in a dashboard.
- Preserve generated OpenAPI/build artifacts as generated; do not hand-edit or commit build output unless the repository later documents it.
- Keep secrets out of code, `.env` commits, frontend variables, fixtures, logs and docs. Use placeholders only.
- Add no infrastructure or runtime dependency without a current requirement and the smallest documented reason. Kafka, Redis/Celery, microservices, feature store and realtime ML are not MVP defaults.

## Definition of done

- Behavior matches the relevant architecture invariant/API/event/privacy contract, or the design is updated and reviewed first.
- Boundary validation, authorization, idempotency/retry and failure behavior are covered proportionally to risk.
- Schema changes include reviewed migration and data/backfill/rollback or forward-fix notes.
- Privacy/safety paths include cross-account, block and stale-state checks; logs/telemetry contain no sensitive payload.
- Actual test/type/lint/migration commands pass and are documented once those tools exist. Unknown infrastructure remains `Assumption`/`TBD`, never asserted as fact.
